#+TITLE: game-launcher
#+AUTHOR: Rush


~game-launcher~ is a Common Lisp-based game launcher framework designed to bridge some of the shortcomings of general-purpose game launchers.

Rather than being tied to a particular storefront or game runtime, ~game-launcher~ provides a framework for representing games, their launch configurations, and the runtimes required to start them.

The project is intended to make it possible to describe game launch configurations in a simple, extensible format while allowing different runtimes and launcher implementations to coexist.

* Usage

#+begin_src bash
game-launcher                 # interactive picker
game-launcher NAME            # launch a game
game-launcher --list          # list all launchers
game-launcher --import (FORM) # import a launcher from a form
game-launcher --import lutris # import from a Lutris install
#+end_src

* Current Implementation Features

** Launcher Definitions

Games can be represented as launcher objects containing the information required to start them.
#+begin_src common-lisp
(let ((launcher (make-instance 'wine-launcher
		 :name "Touhou 6"
		 :exec "path/to/touhou")))
 (launch launcher))
#+end_src

** Runtime Support

Launchers can be associated with different runtime implementations, allowing the same framework to handle games that require different ways of being executed.

** Form-Based Serialization

Launcher configurations are represented as Lisp forms and can be written to and restored from a file.

#+begin_src common-lisp
(EXEC :NAME "Cataclysm Bright Nights" :EXEC
 "~/Games/cataclysmbn-v0.12.0/cataclysm-launcher")
#+end_src

** Unknown Launchers

Launcher configurations using an unknown or unavailable runtime are preserved rather than discarded.

Unknown forms are stored as raw serialized data and can be written back to the launcher file later.

** Extensible Architecture

The launcher and runtime systems are designed around Common Lisp's object system, making it possible to add new launcher and runtime types without changing the core serialization mechanism.

* Store File Format

Launchers live in =~/.config/game-launcher/launcher-store.lisp= as Lisp
forms, one list of launchers. Editable by hand. Reloaded on every run;
saved at session end.

#+begin_src common-lisp
  ((WINE :NAME "Touhou 9"
         :PROFILE (("DXVK_ASYNC" "1"))          ; inline env pairs
         :EXEC "/path/th09.exe")
   (EXEC :NAME "Monster Hunter Rise"
         :PROFILE MHR
         :EXEC "/path/to/mhr"
         :ARGS ("-u" "MMOFAN"))
   (STEAM :NAME "Elin JRPG"
          :EXEC "steam://rungameid/2135150"))
#+end_src

** Profiles

Named profiles live in =~/.config/game-launcher/profiles.lisp=:

#+begin_src common-lisp
  ((PROFILE :NAME MHFZ :ENV (("MHF_PASS" "mmofan"))))
#+end_src

Launchers referencing =MHFZ= share one profile object — edit the
profile once, every launcher picks it up.

** Defining a profile inline (marker syntax)

Writing an inline profile followed by ==>NAME= defines a named profile
on first load and replaces the launcher's entry with a reference:

#+begin_src common-lisp
  (EXEC :NAME "MHFZ" :PROFILE (("MHF_PASS" "mmofan")) =>MHFZ
        :EXEC "/path/mhf-cli")
#+end_src

After the next save, the form reads =:PROFILE MHFZ= and the profile is
stored in profiles.lisp. Re-marking a form updates the shared profile.

* Design Goals

- Keep the core framework small.
- Represent launcher configuration as data.
- Preserve configurations even when their runtime is unavailable.
- Make adding new runtimes straightforward.
- Make the framework usable both as a library and as a standalone launcher.
